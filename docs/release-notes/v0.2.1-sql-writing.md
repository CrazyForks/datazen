# 写 SQL 也要有 IDE 体验：DataZen v0.2.1 详解

DataZen v0.2.1 来了。这一版只聚焦一件事：**把每天写 SQL 的手感，做到像写代码一样智能**。

悬浮看表、智能 JOIN、函数签名、意图操作、参数化复用、一键美化、高危拦截，一次讲透。

## 一、先说说写 SQL 的 4 个卡点

不管你是后端开发还是数据分析，下面这几个场景一定眼熟：

1. **表一多就记不住字段**。写个 `JOIN`，外键叫啥来着？切到左边树展开表结构，回来又忘了，写三行 SQL 切八次。
2. **函数参数记不清**。`SUBSTRING` 到底是几个参？`DATE_TRUNC` 在当前这个库里支不支持？现查文档，一查就是五分钟。
3. **同一句 SQL 天天跑，只是条件不一样**。每天取数都是同一套逻辑，只是 `user_id`、日期变了。每次手动改 `WHERE`，改得慢，还容易改错、改漏。
4. **`SELECT *` 一时爽，上线火葬场**。上线前要一个个展开成显式列；参数没填就执行，直接传了个 `NULL` 进去，差点酿成全表事故。

v0.2.1 就是冲着这 4 件事来的。

## 二、看懂库：悬浮、跳转、智能 JOIN

写 SQL 最大的时间黑洞，不是敲键盘，是**记库结构**。

v0.2.1 的编辑器现在是懂你的库的。

**表名悬浮卡**：鼠标往表名上一停，直接浮出这个表的字段、类型、注释。不用再去左侧树里一层层展开，对着几十个字段找 `amount` 到底是 `DECIMAL` 还是 `BIGINT`。

![表结构悬浮预览](https://raw.githubusercontent.com/flyxl/datazen/main/site/assets/screenshots/pro-03-hover-tooltip.png)

**Cmd / Ctrl + Click 跳转**：按住修饰键点表名，直接跳到定义位置。几百行的大脚本里穿梭，从 `orders` 跳到 `customers`，一秒的事。

**按外键关系排序的 JOIN 补全**：这是最好用的一个。写到 `JOIN customers` 的时候，补全会按外键关系排序，候选表名后面直接标出注释，`ON` 条件也给你备好。你不用再背关联键，选一下回车就行。

```sql
SELECT o.order_id, c.name, o.amount
FROM orders o
JOIN customers c ON o.customer_id = c.id
-- JOIN 的 ON 条件自动给出，直接回车确认
```

![智能补全](https://raw.githubusercontent.com/flyxl/datazen/main/site/assets/screenshots/pro-02-autocomplete.png)

这一套下来，`orders JOIN customers` 这种日常联查，基本可以一气呵成。

## 三、写对函数：签名提示 + 实时检查

第二个省时间的地方，是**函数**。

打出 `(` 的一瞬间，编辑器上方就会浮出签名条：当前是第几个参数、要什么类型、有没有重载，不同库提示还不一样。MySQL 和 PostgreSQL 的同名函数用法有差异，它会按你当前连接的方言来提示，不会张冠李戴。

![函数签名提示](https://raw.githubusercontent.com/flyxl/datazen/main/site/assets/screenshots/pro-04-signature-help.png)

更关键的是**实时检查**：表名打错、字段写错，当场就是一条波浪线，右侧还会汇总列出问题。不用等到点了执行，被数据库报错打回来才发现少了个字母。

![实时检查](https://raw.githubusercontent.com/flyxl/datazen/main/site/assets/screenshots/pro-05-linter.png)

对新手来说，这是容错；对老手来说，这是把“执行-报错-改-再执行”的无效循环掐死在编辑器里。

## 四、少敲键盘：意图操作

有些操作，明明机器能做，却一直在让人手搓。v0.2.1 把这几个收成了一键意图，光标停在 `*` 上，灯泡菜单里一次备齐：

![意图操作菜单](https://raw.githubusercontent.com/flyxl/datazen/main/site/assets/screenshots/pro-06-intentions.png)

**`*` 一键展开 / 折回**：`SELECT * FROM orders`，一键展开成显式列清单：

```sql
-- 之前
SELECT * FROM orders;

-- 一键展开之后
SELECT order_id, user_id, amount, created_at
FROM orders;
```

上线前展开，安全；自己排查时想看全列，一键再折回去，干净。

**限定符一键加 / 去**：多表都有 `id`、`created_at` 的时候，一键给所有列加上表前缀 `o.`、`c.`，歧义立马消除。想去前缀的时候再一键去掉。

**INSERT 列对齐提示**：`INSERT` 的时候自动对照列顺序给提示，值和列错位一眼就能看出来，不用横着数括号里的第 5 个值到底对应哪一列。

都是小功能，但每天用十几次，省下来的全是手腕。

## 五、重点：参数化复用，收藏一次，天天复跑

这是 v0.2.1 最值得升级的一个能力，单独展开讲。

**场景你一定熟**：运营每天找你取数、线上工单每天都要查，SQL 逻辑永远是同一套：

```sql
SELECT order_id, user_id, amount, created_at
FROM orders
WHERE user_id = 1001
  AND created_at >= '2026-09-01';
```

今天查 `1001`，明天查 `1002`，后天日期换成 `2026-09-10`。以前的做法是：找到昨天的 SQL，手动改 `WHERE`，复制执行。改一次两次还好，一天改二十次，早晚有一次把 `AND` 改丢、把引号改错，或者把条件漏改导致数据对不上。

v0.2.1 的解法是：**条件一次写好，写成参数，以后只填参，不动 SQL**。

第一步，把条件写成命名参数：

```sql
SELECT order_id, user_id, amount, created_at
FROM orders
WHERE user_id = :uid
  AND created_at >= :start_date;
```

支持 `:uid` 这种命名写法，也支持 `?` 占位写法，按你习惯来。

第二步，**收藏这句带参 SQL**。把它收进收藏夹，它就是你的常用模板了。下次从收藏打开，直接就是这句，不用再去聊天记录、记事本里翻。

第三步，运行前**只在编辑器头部填参**。编辑器顶部会自动出现参数面板，`uid` 填 `1002`，`start_date` 填 `2026-09-10`，点执行就行。SQL 本体一个字都不用动。

![参数绑定面板](https://raw.githubusercontent.com/flyxl/datazen/main/site/assets/screenshots/31-sql-editor-bind-params.png)

还有两个细节很贴心：

- **参数历史自动记住**：上次填的 `1001`、`2026-09-01` 都留着，今天翻页复跑，直接回车，不用重敲。
- **没填参直接拦截**：哪个参数空着，执行会被拦下来，不会把它悄悄当 `NULL` 传进去。做过全表更新事故的人都懂，这一行拦截值千金。

一句话：以前是“每次改 SQL”，现在是“每次填两个空”。同一句 SQL，换 100 组条件，它还是那句没被改乱过的 SQL。

## 六、写得快、写得稳：美化、粘贴、高危拦截

除了上面的智能能力，日常的快和稳也一起补上了。

**写得快：**

- **一键格式化**：从别处粘来的乱 SQL，一键美化缩进，左右对照清清楚楚。

![一键格式化](https://raw.githubusercontent.com/flyxl/datazen/main/site/assets/screenshots/pro-09-format-sql.png)

- **多光标一起改**：多处要改表别名，多光标一起改，一个个点过去的时代结束了。
- **粘贴多行 ID 进 `IN`**：从表格、日志里复制一列 `1001 / 1002 / 1003`，在 `IN ()` 里按 `Cmd/Ctrl + Shift + V`，直接变成 `'1001', '1002', '1003'`，顶部还会弹条确认。拼 `IN` 列表再也不用一个个加引号加逗号。

![粘贴为 IN 列表](https://raw.githubusercontent.com/flyxl/datazen/main/site/assets/screenshots/pro-08-paste-as-in.png)

- **从表树拖字段**：左侧看到要用的字段，直接拖进编辑器，落点还有高亮，不会拖错位置。

**写得稳：**

- **无 `WHERE` 红色拦截**：`UPDATE / DELETE` 没带 `WHERE`、`DROP TABLE` 这种高危句，执行前会弹红色强制确认，语句摆在你面前让你再看一眼。确认是故意的再放行，手滑党狂喜。这个开关可以在设置里自己控制。
- **DML 结果卡**：`UPDATE` 跑完不再是冷冰冰的“无数据显示”，而是直接告诉你影响了多少行、花了多久，心里有数。

![高危执行拦截](https://raw.githubusercontent.com/flyxl/datazen/main/site/assets/screenshots/30-sql-editor-danger-guard.png)
