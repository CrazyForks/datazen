# 不离开编辑器看 Schema：表结构悬浮卡片与快捷跳转

> 写 SQL 时最烦的事情之一：刚写了一个表名，突然忘了某个字段叫什么，不得不切到 Schema 树里去找。心流被打断，思路也跟着断。

## 写 SQL 时的"查表"困境

每个写 SQL 的人都有过这种体验：

你正在写一条多表 JOIN 查询，已经想好了逻辑，表名和 JOIN 条件都写好了。但写到 SELECT 列表时，突然不确定某个字段是叫 `user_name` 还是 `username`，或者是叫 `display_name`。

这时候你需要做什么？

1. 把光标从当前位置移开；
2. 切换到左侧的 Schema 树面板；
3. 展开目标表的列列表；
4. 找到那个字段名；
5. 切回编辑器；
6. 重新定位光标到刚才的位置继续写。

六步操作，只为了确认一个字段名。如果这条 SQL 涉及三四张表，你可能要重复这个过程好几次。每次中断都在打断你的思路，而重新组织思路需要额外的时间和精力。

DataZen 的方案是：**让你不用离开编辑器，就能看到 Schema 的完整信息。**

## 悬浮卡片：光标在哪里，信息就在哪里

在 DataZen 的 SQL 编辑器中，当你把鼠标悬停在一个表名或表别名上时，编辑器会自动弹出一个 Schema 悬浮卡片。

![表结构悬浮卡片](https://raw.githubusercontent.com/flyxl/datazen/main/site/assets/blog/04-hover-tooltip.png)

这张卡片包含的信息比你想象的要丰富：

**列信息**：列出该表所有列的名称和数据类型。你一眼就能看到有哪些字段，每个字段是什么类型，不用再切到 Schema 树去翻。

**是否可空**：每列是否允许 NULL 值，直接标注在类型旁边。写 INSERT 或 UPDATE 时，这个信息非常关键。

**默认值**：如果某列有默认值，卡片上也会显示。不用再去查表结构定义。

**外键关系**：这张表和其他哪些表有关联，外键指向哪张表的哪个字段，都在卡片里一目了然。这在写 JOIN 查询时特别有用——你不用去记忆或查文档，关联关系直接呈现在眼前。

**表注释**：如果建表时写了 COMMENT，也会显示在卡片顶部。对于字段含义不太直观的业务表，这个注释能帮你快速理解表的用途。

## Cmd/Ctrl+Click 快速跳转

除了悬停查看信息，DataZen 还支持 Cmd+Click（macOS）或 Ctrl+Click（Windows/Linux）直接跳转到 Schema 树中对应的对象。

当你在编辑器里 Cmd+Click 一个表名，Schema 树会自动展开并定位到那张表。点击一个列名也能直接定位到对应列。

这个功能在你确实需要更多上下文时非常有用——比如你想看整张表的完整 DDL、查看索引定义，或者对比多张表的结构。悬浮卡片给你快速概览，Cmd+Click 给你深度查看，两者配合覆盖了绝大多数"查 Schema"的需求。

## 多表 JOIN 场景：同时悬停，快速对比

写多表 JOIN 查询时，你经常需要同时参考多张表的结构。在传统工具里，你可能需要在 Schema 树里分别展开好几张表，来回切换查看。

DataZen 的悬浮卡片支持同时显示多个。你可以把鼠标依次悬停在 JOIN 的每张表上，快速对比各表的列名和类型，确认关联条件是否正确。

![多表同时悬停对比](https://raw.githubusercontent.com/flyxl/datazen/main/site/assets/blog/04-hover-multi-table.png)

举个例子：你在写 `_blog_employee` JOIN `_blog_dept` JOIN `_blog_emp_project` 的查询。把鼠标悬停在 `_blog_employee` 上看看它有哪些外键，再移到 `_blog_dept` 上确认部门表的主键字段名，然后移到 `_blog_emp_project` 上确认关联字段。整个过程不需要移动光标，不需要切换面板，不需要打断思路。

这种"原地查看"的体验，让你能把注意力集中在 SQL 的逻辑设计上，而不是分散在各个面板之间做信息搬运工。

## 对比传统工具的 Schema 查看方式

在 Navicat 和 DBeaver 中，查看表结构通常需要以下操作：

- **Navicat**：双击表名打开表设计面板，或在左侧树中展开列列表。如果编辑器里有多张表，你需要逐个去查找。
- **DBeaver**：在左侧 Database Navigator 中展开表 → 列，或者右键表名选择 "Properties"。信息分散在不同的 Tab 页里。

这两种方式的共同问题是：**你需要离开编辑器去获取信息，然后带着信息回到编辑器继续工作。** 这个来回切换的过程，就是心流被打断的根本原因。

DataZen 的悬浮卡片把这个过程压缩到了零切换：信息在你需要的时候自动出现在你的光标旁边，看完之后继续写，没有任何中间步骤。

| 操作 | 传统工具 | DataZen |
|------|---------|---------|
| 查看单表列信息 | 切到 Schema 树，展开表 | 悬停表名即可 |
| 查看外键关系 | 右键表 → Properties → FK Tab | 悬停表名，卡片底部直接显示 |
| 确认列名和类型 | 切到 Schema 树 → 展开列 | 悬停表名，列信息一目了然 |
| 查看表注释 | 右键表 → Properties → Comment | 悬停表名，卡片顶部直接显示 |
| 多表对比 | 分别展开多张表，来回切换 | 依次悬停即可 |
| 跳转到 Schema 树 | 手动在树中搜索定位 | Cmd+Click 自动定位 |

## 从"切换"到"原地"的体验升级

这种设计思路的本质是**减少上下文切换**。

写 SQL 是一个需要高度集中注意力的工作——你在脑子里构建表之间的关联关系，规划查询逻辑，组织列的选取和聚合。每一次切换面板、每一次搜索定位，都是对这个思维过程的打断。

DataZen 的悬浮卡片和快捷跳转，把"查看 Schema 信息"这个辅助操作的成本降到了最低。你不需要离开编辑器，不需要记住路径，不需要在多个面板之间做信息搬运。Schema 信息就在你的光标旁边，你需要的时候它就出现，你看完就继续写。

这不是一个"花哨"的功能。它解决的是一个每天都会遇到、每次都让人分心的小问题。而当你把这些"小问题"的解决方案累积起来，编辑器的整体体验就会有质的提升。
