## Observed gap

- Database-target `CREATE` routes through `data_transfer::structure::mapped_create_ddl`, which builds an `IRTable` from columns and primary keys. It does not plan secondary indexes or foreign keys.
- The SQL-file structure route in `data_transfer::sql_structure` already converts `TableSchema` objects to `IRTableObjects`, applies column mappings, and renders index/foreign-key DDL. The database route must not silently provide less structure than its preview or SQL-file counterpart.
- `ColumnSchema` exposes only `is_auto_increment`; it does not represent generated-column mode/expression. PostgreSQL schema introspection currently reports `is_auto_increment: false`, so identity semantics may be lost when a new target table is created.

## BUG-006 repair checkpoint

- The R3 report showed Data-only + Insert copied explicit IDs 31/41 into an existing PostgreSQL GENERATED BY DEFAULT identity table but left the sequence at 1. A Data Transfer-only `DatabaseDriver::advance_transfer_identity_sequences` hook now runs after all batches for a table succeed and before the existing transaction commits. Hook failures and cancellation continue through the existing per-table rollback fence; row failures never call the hook. Generic Data Sync and Schema Diff code paths do not invoke this hook.
- PostgreSQL owns the sequence handling. The driver resolves only sequences owned by the mapped target column via `pg_get_serial_sequence`, safely quotes target and catalog identifiers, inspects `last_value`, `is_called`, increment, bounds, cycle and cache state, preserves the greater of the existing next value and the next value above the target-table maximum, and uses transaction-scoped `ALTER SEQUENCE ... RESTART`. It refuses PostgreSQL before version 10, missing/unowned sequences, unreadable state, CYCLE, descending increments, CACHE other than 1, insufficient ownership, and values outside the sequence bounds so the Host rolls the table transaction back.
- PostgreSQL SQL-file exports now use a second driver-owned Data Transfer renderer to emit an equivalent transactional `DO` block after each complete table's INSERT statements. It resolves the target sequence at script execution time, safely quotes schema/table/column names, skips ordinary columns, and raises on an unowned `nextval` default or unsupported sequence state so the surrounding script transaction cannot commit partial rows.
- Added Host fake-driver coverage for call order (`write → sync → commit`), hook-error rollback, row-failure refusal, and cancellation refusal; added a SQL-file output test; added PostgreSQL calculation/rendering unit tests and an ignored live transaction test covering IDs 31/41, a pre-existing high sequence value, identity and owned serial, quoted identifiers, SQL-file block execution, and CACHE/CYCLE refusal with row rollback.
